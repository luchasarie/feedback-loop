# Philosophy: anger is signal, not a protocol violation

Agent failures often end with one of two useless rituals:

1. the user vents, the agent apologizes, and nothing changes;
2. the agent panics and writes broad permanent rules everywhere.

Feedback Loop rejects both.

## The user does not owe the agent emotional labor

A model has no feelings to protect. Requiring a frustrated person to repackage a failure into calm, perfectly structured prose wastes the strongest signal in the interaction. The skill accepts feedback as delivered and separates tone from claims.

That does not mean every claim is automatically correct. Evidence still wins. The agent can say:

- “That impact is real, but this inferred cause is not supported.”
- “The requested correction would weaken a safety boundary.”
- “This appears to be a one-off; a permanent rule would make the system worse.”

Direct disagreement is compatible with respectful diagnosis.

## Learning must be visible and consented

An agent saying “I learned” is not evidence of learning. Durable improvement requires a named destination, concrete change, reason that destination owns it, approval boundary, and verification after implementation. The user should be able to reject one proposal without losing the rest.

## The smallest correction usually wins

Every permanent instruction consumes attention and can collide with future work. The goal is not to preserve the incident forever. It is to change the minimum system surface that can prevent recurrence.

Sometimes the correct result is **no durable change**. A typo, transient outage, or already-covered mistake may need execution—not another rule.

## Better users and better agents

Feedback can reveal a shared contract gap. The agent should own sensible defaults and should not use ambiguity as an excuse. The user can still gain leverage from a compact acceptance signal when the decision is genuinely preference-sensitive. That lane is optional, specific, and never “write better prompts.”
